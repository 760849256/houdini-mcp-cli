## C：同条件性能

以不可变 0.3.0a1 第一阶段候选 zip 为对照，Windows / Houdini 21.0.440，真实 stdio → HTTP → GUI 主线程。
每个版本分别使用 200、2000、10000 个 SOP 节点；每种规模测量 context、20 节点 inspect、20 参数 edit，各 100 次，另有 3 次预热。
均排除模型响应时间。两个版本顺序运行；结果存在工作站负载和 GUI 调度波动，不推算生产重型场景加速比例。

| --- | --- | --- | --- | --- |
| 200 | 376.896 → 203.030 ms | 46.13% | 66.49% | 32.362 / 216.882 / 123.514 ms |
| 2000 | 376.385 → 207.285 ms | 44.93% | 66.48% | 27.875 / 114.680 / 134.266 ms |
| 10000 | 375.067 → 217.634 ms | 41.97% | 66.46% | 28.655 / 124.140 / 151.642 ms |

早期未优化 context 的测量也保留，避免只保留有利结果。最终增加的快照过期回退和 HIP 事件修正另有功能验证。

实现包括：一次提交内完成校验、执行、回读；复用同一主线程中的验证；短任务在接收响应内完成；限量状态缓存；进度落盘节流；字段筛选前推；紧凑文本及完整结构化结果。
目标节点身份和参数前置状态可显式提交。连续赋值保留全部 setter 和即时回读，最后一步仍读取现场。

## 故障测试发现与修复

1. 连续赋值的旧验证会拿最终值比对所有中间期望，导致误报；现使用执行任务内部的即时证据验证被后续覆盖的步骤。
2. 隐藏 GUI 的网络截图可以是全黑图；现与视口一样返回 unusable_preview，并保留 pane 恢复结果。全黑样本经实际查看确认，未当作可用画面。
3. context 快照超过一秒时，首轮实现返回错误；现回退到有界队列中的新鲜读取，避免启动期 UI 停顿导致无谓失败。
4. HIP 事件回调未接收额外文件信息，且依赖枚举显示字符串，实测漏掉同名文件重载。现接收事件附加信息、比较真实枚举，并在加载/清空/合并开始前失效旧 epoch。
   [SideFX 回调接口](https://www.sidefx.com/docs/houdini/hom/hou/hipFile.html#addEventCallback)说明了事件参数及文件相关附加信息。

失败报告和后续复验分别保存，不覆盖。故障测试只创建、加载或退出自身拥有的隔离进程与临时 HIP。
